# 02 · 软件架构与产品控制语义

以下是**本项目设计**，不是对 AnyTeleop 原始私有实现的猜测。设计依据见 01_RESEARCH。

## 1. 总体数据流

```text
相机原始 RGB / RGB-D、内参、帧时间
                 |
                 v
     上游手部识别（完整21点，不先删点）
                 |
         +-------+------------------+
         |                          |
   全局手腕位姿估计            局部手指几何
   RGB朝向 + RGB-D位置         拇指—四指夹角
         |                          |
         +------ 手势观测包 ---------+
                         |
                         v
     控制意图层：接管、坐标方向、位移倍率、软接管
                         |
              末端目标位姿 + 夹爪开度
                         |
                         v
      运动后端：SO101位置优先伺服 / 后续cuRobo
                         |
                         v
   独立安全和驱动层：全连杆碰撞、限位、命令期限、急停
                         |
                  SO101 / 仿真
                         |
                  实际关节反馈
                         +----> FK / 接管参考 / 跟随误差

录制与诊断：同时记录原始观测、映射目标、可执行目标和实测结果。
UI：显示这些数据，不作为机器人安全停机的唯一依赖。
```

## 2. 三个不能混淆的状态

**观测状态：** 识别是否检测到手、腕部空间定位是否有效、朝向来自 RGB 推断还是深度配准、开合是否可用。

**用户意图：** 用户是否按住控制按钮、当前的相对末端目标与夹爪开度。可先用键盘/脚踏/实体按钮实现 clutch，不要让用于夹取的拇指动作同时负责开始控制。

**执行状态：** 目标是否可达、实际机器人在哪里、是否限速/限位、是否需要受控停止。

“检测到手”不等于“所有自由度都可信”；“目标合法”不等于“机器人已经到位”。

## 3. 坐标与单位

内部单位：米、秒、弧度。四元数固定 `xyzw`。列向量约定：`p_A = R_A_B @ p_B + t_A_B`。

- `C`：原始、未镜像的彩色相机光学坐标。x 右、y 下、z 前。
- `H`：固定版本的上游腕部局部坐标系。不能把 MANO、MediaPipe 和 OpenXR 的轴约定混用。
- `B`：机器人 base_link。
- `G`：机器人刚性夹爪控制参考。优先使用实测校准的固定 TCP，而非随开合漂移的两指中点。
- `R_B_C`：操作方向的旋转映射。允许是人为定义的远程操作方向，不一定是两台设备在同一房间的真实外参。

镜像只用于显示。反射矩阵 determinant=-1 不是旋转；不能为了让画面“像镜子”直接塞入 SE(3) 运算。

相对控制抵消了操作者与机器人之间的平移偏置，但**没有抵消方向、尺度、相机内参或机器人 TCP 的错误**。初次接入必须逐轴验证 +X/+Y/+Z 和旋转方向。

## 4. 接管语义

按住 clutch 的首个可信帧同时记录当前手腕位姿和**实测**机器人末端位姿。首帧发出的目标必须等于当前机器人状态，位置、朝向都不能跳。

保持按住时，手相对这个参考点运动。松开后受控停住，操作者可把手移回舒服的位置，再按住重新接管。坐标转换始终固定在操作坐标系，不随当前手腕旋转而改变平移方向。

夹爪采用独立软接管：用户手的开度靠近或跨过当前机器人开度后，再开始跟随，并限速。这样重新接管不会突然张开并掉落物体。短时开合不可用只保持开度；不把它当成“应当松手”。

## 5. 状态机

| 状态 | 进入原因 | 离开方式 |
|---|---|---|
| IDLE | clutch 释放或初始状态 | 新鲜可信观测 + ready + 按下 clutch |
| ACTIVE | 成功建立参考 | 松开、错误、失效或急停 |
| PAUSED | 追踪失效、身份/坐标变更、过期、目标积压等 | 明确松开，再按下；不能自动续跑 |
| ESTOP | 急停 | 急停条件解除 + 明确 reset + clutch 释放，再重新接管 |

本版 full-pose 模式要求位置和朝向都可用。未来位置模式需要独立、显式选择，不允许在后台悄悄切换导致用户误解能力。预测可以画虚线预览，不能被标为观测证据。

`q_command=None` 是上层停止意图。真实驱动必须将其转成经过验证的停止策略；既不能继续追逐上一个遥远目标，也不能一律关闭 torque 导致掉落。

## 6. 进程与实时性

建议分开三个环境/进程：`vision-worker`、`teleop-core/motion-worker`、`robot-worker`。初版可同机运行，不引入云服务。

视觉按实际相机帧率提供最新结果；控制循环独立运行。重复使用同一帧直到超时是正常的，不能把 30 Hz 图像送入 100 Hz 控制器后，每个重复帧都判为异常。包内对此有回归测试。

每个相机 worker 保持自己的时序识别实例。核心消费 latest-only 队列，避免旧视频帧积压。图像时间必须代表采集时间，并转换到共同 monotonic 时钟；发布时刻不能冒充采集时刻。远端时钟若未同步，应明确转换而非比较两个机器的原生 monotonic 数值。

建议开始以相机实际 30 Hz、控制 60 Hz 的配置做台架验证，之后按测量结果调整。论文的 120 Hz 不是我们给 SO101 的已验证承诺。软件不能给普通 Python 回路宣称硬实时保证。

## 7. 接口

### `HandObservation` / `teleop.hand_observation.v1`

关键字段：序号、采集时间、track_id、frame_id、Pose、开度、三个通道的 evidence。Pose 的位置必须是固定相机参考系中的有尺度位置。模型局部骨架另存诊断日志，不直接充当腕部平移。

本接口用 `rgbd_fused`、`rgb_model`、`predicted` 等明确来源，不把当前图像的模型估计包装成深度实测。深度辅助定位仍然是估计，也可能有表面/关节偏差。

本版不同于旧工程可能存在的 `handtrack.packet.v1/v2`；由 Codex 写兼容适配并保留旧消费者，不能原地改字段含义。

### `RobotState`

必须带实测关节、读取时间、测得的归一化夹爪开度。关节顺序按名称映射，不依赖 SDK 或 URDF 遍历顺序。驱动输出单位与 URDF 弧度的转换、符号和零位全部在边界显式标定。

### `MotionBackend` / `SweptCollisionGuard` / `RobotPort`

见 `ports.py`。目前只有 CPU 离线伺服实现；cuRobo、碰撞守卫和真实驱动只有接口契约，未实现。

## 8. UI 最少需要显示什么

原始上游 21 点诊断图（默认可切换两指显示）、手腕三轴、四个层级的位置/朝向（原始、期望、可执行、实际）、夹爪软接管提示、状态和停止原因、数据年龄、深度残差、实际跟随误差。

记录按钮应保存完整时间窗而非只保存检测成功帧。重置中立、镜像预览、左右手选择、开合标定和回放都是诊断操作，不应绕过安全状态机。
